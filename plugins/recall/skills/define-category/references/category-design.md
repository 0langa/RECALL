# Category Design

Create a category only when multiple future memories share a stable retrieval purpose.
Prefer built-ins for decisions, requirements, risks, commands, architecture, tasks,
debug history, project state, preferences, and constraints.

Names should be short lower-snake-case nouns. Descriptions should state what belongs
and what does not. Start at weight `1.0`; raise weight only when category should beat
ordinary context for broad queries.
